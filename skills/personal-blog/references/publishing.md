# 发布 personal-page

只在用户本次或仍适用的会话授权包含提交/发布时使用。这个流程不自动授予外部写权限；已有授权则不重复询问。仅改稿或创建 Skill 时不执行这里的发布操作。

## 先确定当前状态

按需要读取仓库 `docs/deployment.md` 和 `docs/deployment-versioning.md`，核对 `git status`、分支和远端。保护未提交草稿，只提交本次范围；用户没要求新分支时沿用仓库实际工作流。构建、视觉/交互验收和必要审查通过后提交、推送，再从完整 SHA 制作发布包。

服务器信息是本次站点的定位线索，使用前核验，不视为永久常量：

- SSH 曾使用 `root@106.15.238.51`，通过本机已配置认证连接，不复制密钥进入技能或仓库。
- 静态发布目录 `/var/www/personal-page/releases/<release-id>`。
- 生效入口 `/var/www/personal-page/current` 是符号链接；先读 `readlink -f` 和当前 `deployment.json`。
- 正式域名 `https://linyouwei.top/`；Waline 是独立服务与数据库，静态部署无需重启它，也无需改 Nginx、PA 或其他项目服务。

不复用历史发布目录名或把旧 SHA 当当前版本。标签沿用 `vYYYY.MM.DD-N`，日期取客户端时区，先核对远端已有标签/Release，选择未占用的序号。

## 制作可追溯的静态包

技能提供只在本地运行的脚本，无第三方依赖：

```powershell
node ./skills/personal-blog/scripts/package_release.mjs --repo . --tag 'vYYYY.MM.DD-N' --previous 'previous-release-id' --out '新的空输出目录' --commit '完整提交SHA'
```

以上命令从 personal-page 仓库根目录运行，使用仓库内的技能副本。若从全局安装目录调用，按当前 SKILL.md 所在目录定位 scripts/package_release.mjs，并将 --repo 指向实际仓库；不依赖固定账号或盘符。查看准确参数可运行 `--help`。

脚本从指定 Git tree 导出根级页面/样式/脚本及 `assets/`、`posts/`、`variants/` 中公开静态资源，保留站点子路径。它不读取未提交文件、不上传、不提交、不切服务器链接。工作区有无关草稿不需要清空。

输出包括静态 tar.gz、`deployment.json` 和 `SHA256SUMS`。清单记录完整源 SHA、标签、发布 ID、构建时间、上版发布 ID、归档和逐文件 SHA-256；`source_dirty: false` 指归档来自 Git 快照。真正部署成功的时间在切换时记录，不能预先声称已上线。

部署清单放在归档外，避免把包的自身校验值嵌回包内形成自引用。检查实际文件列表，确保不含 `.env`、依赖目录、运行数据、数据库、密钥或日志。公共资源白名单不代替对已提交内容的保密检查。

## 先验证新目录，再切换

1. 上传归档与清单至明确的本次暂存路径；先核对 SHA-256，再解压到新的版本目录。按清单核对文件；保留旧发布目录作为回滚点。
2. 切换前记录旧 `current` 和旧清单。将新清单加入新目录；`deployed_at` 只用于记录实际切换时间，发布失败不能被记为成功上线。
3. 用临时符号链接加 `mv -Tf` 原子切换 `current`。发布脚本必须检查旧入口仍是准备时看到的版本，避免覆盖其他人的并行发布。
4. 核验首页、实际文章、被改动的样式/脚本/图片和相关交互。若失败，切回之前已验证的目录；不删除数据、不循环切换猜测。

这是一套发布顺序，不要求复制历史脚本全文。可复用经过检查的项目工具，但不要依赖忽略目录里某次任务硬编码的 SHA、校验值或服务器临时文件。Windows 编写 Bash 部署脚本时用真实文件或单引号 here-string，避免 PowerShell 提前展开 `$()`、反引号或服务器变量。

## 线上验证的关键区别

- 推送成功只说明 GitHub 更新；符号链接切换只说明服务器换版；真实浏览器通过才说明新功能可用。
- 验证 `/deployment.json` 的源 SHA 与提交一致。检查当前文章真实内容、手机尺寸、锚点/回顶/进度或动画的本次关键行为；不是只检查 HTTP 200。
- 已变更的 CSS/JS 应使用新版本 URL。用回访视角检查缓存，尤其站点全局 SVG 默认尺寸可能与旧页面 CSS 不兼容。
- Waline 有来源检查。命令行无 `Origin` 的评论 GET 曾返回 403，而浏览器来源请求正常。探测需带 `Origin: https://linyouwei.top` 和正确 Referer，先比较旧版基线，不把这类预期拒绝误判为静态页发布故障。
- 如使用 `curl --resolve` 检查本机 Nginx，保持正式 Host/SNI；最终仍从正常公网域名验证。

成功后按仓库约定创建 GitHub 标签与 Release，附静态包、校验文件和无凭据部署清单。遇到超时先查询 Release 和附件实际状态，再补齐缺项，避免反复创建或覆盖别人的发布。

最终交付文章链接、简短变更与必要验证结果。工作流的后台细节不必全部写给用户，也不要顺手改其他服务。
